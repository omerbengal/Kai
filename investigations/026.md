## למה זה קרה (Root Cause)

### גילוי קריטי

תהליך ה-Telegram bun הרץ כרגע (PID 45864, parent 69536, התחיל 11:21:18 ב-10/05) הופעל מהקובץ:

```
C:\Users\Omer\.claude\plugins\marketplaces\claude-plugins-official\external_plugins\telegram\server.ts
```

(parent CommandLine: `bun run --cwd C:/Users/Omer/.claude/plugins/marketplaces/claude-plugins-official/external_plugins/telegram --shell=bun --silent start`)

אבל `scripts/patch_telegram_plugin.py` מקודד hard-coded לעדכן רק:

```python
PLUGIN_CACHE = r"C:\Users\Omer\.claude\plugins\cache\claude-plugins-official\telegram"
versions = sorted(glob.glob(os.path.join(PLUGIN_CACHE, "*", "server.ts")))
```

ב-`cache\claude-plugins-official\telegram\0.0.4\` **אין בכלל קובץ server.ts** (רק node_modules ו-config files). ה-glob מחזיר רשימה ריקה, הסקריפט יוצא בשקט. אומת:

```bash
$ grep -c "message_reaction" C:/Users/Omer/.claude/plugins/marketplaces/.../telegram/server.ts
0
$ grep -c "reply_to_message_id" .../server.ts
0
$ grep -c "inline_keyboard"   .../server.ts
0
```

הקובץ הרץ הוא **bare upstream**, ללא אף אחד מה-3 patches שלנו. (ה-callback_query הקיים ב-server.ts הוא של ה-plugin עצמו לטיפול ב-`perm:` prefix, לא הפיקס שלנו.)

### למה זה לא התגלה קודם

- חלק מההודעות שלנו עם `inline_keyboard` "עבדו" כי הצליחו להגיע ל-Telegram דרך מנגנון אחר (sendMessage חוזר עם reply_markup אם המפתח קיים, גם בלי schema), אבל בפועל ה-callback שחוזר לא טופל על ידי handler מותאם — רק על ידי ה-`perm:` prefix המקורי, שמסנן הכל החוצה אם זה לא perm:* בעצם הקליקים על callbacks אכן לא הגיעו לקאי בצורה אמינה.
- שינוי 1 מ-#025 (`kill_stray_plugin_processes`) הרג תהליכים ישנים — אבל זה היה חסר משמעות כי גם אחרי הריסטרט, התהליך החדש העלה את הקובץ הלא-מתוקן מ-marketplaces.
- patch_telegram_plugin.py כתב לוגים `"[patch_telegram] no server.ts found"` ל-stderr, אבל אף אחד לא צופה בו במהלך SessionStart.

### ההיסטוריה

ככל הנראה Claude CLI שינה את location של plugins מ-`cache/.../X.X.X/server.ts` ל-`marketplaces/.../external_plugins/server.ts`. ה-cache עכשיו רק מארח node_modules + config. ה-patch script לא עודכן בהתאם.

### שינוי 2: שיפור `scripts/kai_watchdog.py` — תנאי טריגר חכם יותר (תיקון false-alarm)

**הבעיה הנוכחית** (שורות 88-138 ב-`kai_watchdog.py`): התנאי `reaction_age > 24h && incoming_age < 6h` יכול לזעיק שווא — אם עומר פשוט לא מגיב באמוג׳י על אף הודעה במשך יום שלם (תרחיש סביר לחלוטין).

# in the last 30 minutes that should have triggered a reaction (because
# Omer's pattern is to react to ack reminders), and no incoming reaction
