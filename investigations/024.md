# Investigation 024 — Why Supadata is failing 100% of the time on TikTok URLs

**Date:** 2026-05-07
**Trigger:** Omer (TG msg 5937, 05:16Z): "אבל למה Supadata לא עובד... בוא ננסה לתחקר את זה קודם אולי... לא?"
**Context:** Supadata-stage of `scripts/tiktok_summary.py` has logged 0/5 success rate. Every call falls through to the Playwright + Whisper fallback. Before removing it, Omer wants the actual root cause.

---

## TL;DR (root cause — 1 line)

`scripts/tiktok_summary.py` calls **`https://api.supadata.ai/v2/tiktok/transcript`** — that endpoint **does not exist** on Supadata's API. Their docs explicitly state the base URL is `https://api.supadata.ai/v1` and the unified transcript path is **`/transcript`** (which supports TikTok natively). Fix is a 1-line URL change. Supadata is **not broken and not unsupported** — we've been calling the wrong endpoint the whole time.

---

## Reproduction

### 1. Resolve canonical URL (Step A — works fine)

```python
import requests
r = requests.head('https://vt.tiktok.com/ZS9gK89g6/', allow_redirects=True, timeout=10)
print(r.url.split('?')[0])
# → https://www.tiktok.com/@tenfoldmarc/video/7636837709343968532
```

Status 200. Canonical URL resolution is healthy. Not the bug.

### 2. Call the endpoint that's hard-coded in `tiktok_summary.py` line 88

```python
r = requests.get(
    'https://api.supadata.ai/v2/tiktok/transcript',
    params={'url': 'https://www.tiktok.com/@tenfoldmarc/video/7636837709343968532'},
    headers={'x-api-key': '<REDACTED_SUPADATA_KEY>'},
    timeout=25,
)
print(r.status_code, r.text)
```

Output (3 consecutive attempts, all identical):

```
404 404 Not Found
404 404 Not Found
404 404 Not Found
```

Body is the bare 13-byte string `404 Not Found` — **not a Supadata-formatted error**. Their real errors look like JSON `{"error":"limit-exceeded","message":"...","details":"..."}` (we got one transient one of those during testing). The bare-text `404 Not Found` means **Cloudflare/their gateway sees no route at this path** — i.e. the endpoint genuinely does not exist.

### 3. Call the correct endpoint (per their docs)

```python
r = requests.get(
    'https://api.supadata.ai/v1/transcript',
    params={'url': 'https://www.tiktok.com/@tenfoldmarc/video/7636837709343968532'},
    headers={'x-api-key': '<REDACTED_SUPADATA_KEY>'},
    timeout=20,

print(r.status_code)
print(r.json())
```

Output:

```
200
{
  "lang": "en",
  "availableLangs": ["en"],
  "content": [
    {"text": "We're so back baby. Chat GBT is absolutely cooked.", "duration": 3280, "offset": 20},

    ... 9 segments total ...
  ]

```

**Full transcript returned, 421 chars, 9 segments.** Same API key, same canonical URL, just `/v1/transcript` instead of `/v2/tiktok/transcript`. Works on the first try.

### 4. Verify the API key isn't the issue

Tested `/v1/youtube/transcript` (a different documented endpoint) with the same key — returned 200. Key is valid and the plan covers transcript calls.

## Root cause

**Wrong endpoint URL in `scripts/tiktok_summary.py:87-92`.**

```python
resp = requests.get(
    "https://api.supadata.ai/v2/tiktok/transcript",   # ← does not exist
    params={"url": url},
    headers={"x-api-key": SUPADATA_API_KEY},
    timeout=25,
)
```

Supadata docs (`https://docs.supadata.ai/llms.txt`) explicitly state:
- Base URL: `https://api.supadata.ai/v1`
- Path for TikTok: the **unified** `/transcript` endpoint, listed as supporting "YouTube, TikTok, Twitter, Instagram, Facebook"
- There is **no `/v2/` namespace** documented at all
- There is **no dedicated `/tiktok/transcript` path** — TikTok is handled through `/transcript`

So the URL `/v2/tiktok/transcript` is wrong on **both** axes: wrong version (`v2` doesn't exist) and wrong path shape (`/tiktok/transcript` doesn't exist either; only `/youtube/transcript` exists for the per-platform shape).

This explains the 100% failure rate exactly — every call hits a non-route, returns Cloudflare's bare 404, and the existing `try`/`except` in `get_transcript()` catches it and falls through to Playwright+Whisper. Logging shows the fallback as expected behavior so it was never flagged as a bug.

### How did the wrong URL get there?

Most likely: written from a guessed/extrapolated path pattern (matching `/youtube/transcript` shape and assuming a `v2` upgrade existed) without verifying against the actual docs. Supadata's response handling code in `_supadata_transcript()` even understands multiple possible response shapes (`transcript` / `content` / `text`) — so it was clearly written defensively, just pointed at the wrong URL.

## Proposed fix (small — Supadata is saveable)

### Change in `D:/Kai/scripts/tiktok_summary.py`

**Line 88** — replace the URL:

```diff
-        "https://api.supadata.ai/v2/tiktok/transcript",
+        "https://api.supadata.ai/v1/transcript",
```

The existing response-parsing block already handles the v1 shape (it checks for `content` keys with a list of `{"text": ...}` segments — exactly what `/v1/transcript` returns). **No other code change needed.** The cascade order, error handling, and Playwright fallback all stay intact.

### Optional quality-of-life follow-ups (not required for the fix)

1. **Move the API key out of the source.** Line 40 has the key hard-coded as a default fallback (`"<REDACTED_SUPADATA_KEY>"`). It should be env-only — leaking a key in a Git-tracked file is a footgun. Low priority for this investigation; flag it.
2. **Add a one-time smoke test** `scripts/tests/test_supadata_endpoint.py` that hits `/v1/transcript` with a known-good TikTok URL and asserts a non-empty transcript. Catches future endpoint changes.
